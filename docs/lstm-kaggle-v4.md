# LSTM V4: leakage-aware Kaggle experiment

## Purpose

Version 4 is a research-only successor to `train_lstm_kaggle_v2.py`. It keeps V2, V3 and both existing datasets unchanged. The experiment focuses on five-session return; next-session return remains a separately gated auxiliary output.

V4 does not place trades and must not be described as an investment system. A `RESEARCH_CANDIDATE` result only means that the artifact cleared the declared holdout rules in this script.

## Kaggle setup

1. Create a **private** Kaggle Dataset.
2. Upload `.runtime/ml/vci_ohlcv_lstm_1m.csv` and its metadata JSON.
3. Create a Kaggle Notebook and attach that Dataset.
4. Select **Accelerator -> GPU**. One T4 is sufficient; the pipeline does not require two GPUs.
5. Upload and open `notebooks/train_lstm_kaggle_v4_ready.ipynb`, then choose **Run all**. The current ready notebook is self-contained; see [the later V4 development review](lstm-v4-research-and-training.md). This document preserves the earlier experiment protocol, not the latest runtime/promotion state.
6. Do not edit a configuration after looking at its test result. A new experiment needs a new untouched holdout period.

The notebook is a real `.ipynb` containing executable Python. Do not paste its raw JSON into a code cell. As an alternative, paste the contents of `notebooks/train_lstm_kaggle_v4.py` into one Kaggle code cell.

## What changed from V2

- Windows are generated by batch instead of allocating every sequence in RAM.
- Windows cannot cross source gaps or rows removed by activity/liquidity filters.
- Train, validation and test are chronological, with a five-session embargo at both boundaries.
- All clipping, scaling, class weights, neutral threshold and segment thresholds are fitted on train only.
- Four configurations (`window` 30/60 x LSTM 32/64) are compared only on validation five-session MAE.
- The primary target is volatility-normalized five-session excess return. A separate output forecasts the future cross-sectional market proxy so the pipeline can reconstruct raw stock return.
- A three-class `DOWN/NEUTRAL/UP` head provides an auxiliary learning signal.
- The strongest baseline is selected on validation independently for each horizon before test is opened.
- The holdout report includes a moving-block bootstrap and results by year, liquidity and volatility.

The cross-sectional market proxy is not VN-Index. It is used because the free dataset contains no official index series.

## Output artifacts

Every run writes the following files to `/kaggle/working`, whether it passes or fails:

- `stock_lstm_v4.keras`
- `stock_lstm_v4.spec.json`
- `stock_lstm_v4.metrics.json`
- `stock_lstm_v4.history.csv`
- `stock_lstm_v4.validation_sweep.csv`
- `stock_lstm_v4.test_predictions.csv`

Download all six files together. The JSON specification contains the dataset checksum, exact feature order, ticker vocabulary, train-only preprocessing statistics, target inversion formula, split boundaries, baseline choice, warnings and per-horizon eligibility.

## Reading the result

Each horizon receives one of two states:

- `RESEARCH_CANDIDATE`: the calibrated LSTM uses a non-zero signal, beats the validation-selected strongest baseline on test, has a strictly positive 95% block-bootstrap interval for MAE advantage, and is not worse in any sufficiently large test-year segment.
- `EXPERIMENTAL`: at least one of those gates failed. The artifact remains available for the classroom demonstration but must not influence an agent recommendation.

Five-session eligibility determines the overall artifact state. Next-session eligibility is reported separately and cannot make the five-session model pass.

The test prediction CSV is an audit artifact. It must not be fed back into training or used to tune thresholds.

## Claims that the result does not support

Do not claim that the model:

- predicts future prices reliably;
- produces profitable trading signals;
- beats the market or a professional benchmark;
- is safe for real-money decisions;
- was tested on point-in-time constituents; or
- correctly handles every corporate action.

The VCI adjustment field is still `UNKNOWN`, the universe is based on current listings and therefore has survivorship bias, and the market series is only a cross-sectional proxy. These limits remain even when the artifact is labelled `RESEARCH_CANDIDATE`.
